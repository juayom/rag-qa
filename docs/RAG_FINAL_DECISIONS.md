# 최종 RAG 구성과 선택 근거

최종 구성은 **24-chunk 인덱스**와 `questions.json` v1.4 기준이다. 아래에서 26-chunk 실험은 개발 과정의 비교 근거로만 구분해 인용한다. 고정 질문은 30문항(문서 범위 내 27, 범위 밖 3), noisy 질문은 `challenge_set.json` v1.2의 27문항이다. 

## 1. 최종 RAG 구성 요약

| 단계 | 최종 설정 |
|---|---|
| 저장·분할 | Qdrant 24 chunks: 회사 소개 10 / 신용관리 6 / 실사유 코드 8. TXT는 `sentence_split`, PDF·DOCX는 `StructuredSplitterV2` |
| 검색 | Semantic Search, 코사인 유사도 기반 Collection Routing, 질문 유형별 dynamic top-k |
| Query Processing | 원본 질의 우선, 검색 결과가 부족할 때 `adaptive_v2` Multi Query |
| 재랭킹 | `current = Dongjin-kr/ko-reranker`; 후보 상한 일반 **10** / 목록형 **15** |
| 최종 Context | 재랭킹 후 일반 **3** / 목록형 **10** chunk를 GPT에 전달 |

- **기존 문제:** 이전 26-chunk 보고서의 `off`·일반 후보 8 설정은 이후 noisy 및 candidate cap 실험을 반영하지 못한다.
- **비교/변경 내용:** 24-chunk 재인덱싱 후 MQ, 재랭커, 후보 상한을 순서대로 재평가했다.
- **결과:** 현재 기본값은 semantic / Routing / `adaptive_v2` / `current` / 후보 10·15 / Context 3·10이다.
- **최종 선택:** 위 구성을 제출 기준으로 사용한다.
- **선택 근거:** [최종 MQ 평가], [cap 10 평가], [noisy cap 10 평가]
- **남은 한계:** 문서 3개·24 chunks와 작은 질문셋에서 얻은 판단이므로 코퍼스 확대 시 다시 검증해야 한다.

## 2. Adaptive Multi Query 선택 근거

| 방식 | 26-chunk 4-way MQ 실행 | 26-chunk 검색 MRR | 26-chunk 최종 MRR |
|---|---:|---:|---:|
| Always (`on`) | 30/30 | 0.856 | 0.944 |
| Off | 0/30 | **0.884** | 0.944 |
| 기존 Adaptive | 29/30 | 0.865 | 0.944 |
| `adaptive_v2` | 6/30 | 0.856 | 0.944 |

- **기존 문제:** Always는 매 질문에 추가 LLM·검색을 실행하고, 기존 Adaptive는 높은 임계값 때문에 29/30문항에서 실행됐다.
- **비교/변경 내용:** `adaptive_v2`는 원본 검색의 최고 점수가 경험적 기준 0.40 미만일 때만 MQ를 실행한다. 위 4-way는 **26-chunk 동일 인덱스**의 개발 기록이며, 최종 선택은 아래 24-chunk 재평가에 따른다.
- **결과:** 24-chunk 고정 30문항에서 Off와 v2의 검색 Hit/MRR은 **27/27·0.892**, 최종 Hit/MRR은 **27/27·0.963**으로 같았다. v2 실행률은 **6/30(20%)**, 평균 total은 Off보다 **0.609초** 길었다. Noisy에서는 Off **20/27 → v2 22/27**, MQ **11/27(40.7%)**였고 Q-11·Q-12를 복구했으며 역전 실패는 없었다.
- **최종 선택:** 모든 질문에 MQ를 수행하지 않고 `adaptive_v2`를 기본값으로 둔다.
- **선택 근거:** 정제 질문의 최종 품질을 유지하면서 noisy 질의의 실패 2건을 복구했다. 
- **남은 한계:** 0.40은 현재 점수 분포의 경험적 기준이며 최적값은 아니다. 생성되는 MQ 문구와 순위가 실행마다 달라질 수 있고, 이후 cap 10 noisy 재측정의 **23/27**을 이 22/27과 같은 실행의 직접 효과로 해석하면 안 된다.

## 3. Dynamic Top-k 적용 근거

- **기존 문제:** 여러 항목을 묻는 질문에 일반 질문과 같은 최종 Context 3개만 주면 필요한 항목이 빠질 수 있다.
- **비교/변경 내용:** 질문 유형에 따라 1차 검색 top-k를 일반 **8** / 목록형 **15**, 최종 Context를 일반 **3** / 목록형 **10**으로 구분한다. 재랭커 후보 상한 10·15는 별도 값이다.
- **결과:** 26-chunk Routing 평가에서 목록형 L-02의 기대 사업 영역 충족이 baseline **1/3 → 중복 제거 2/3 → Routing 적용 3/3**이 됐다. 최종 24-chunk 구성도 목록형 Context 10을 유지한다.
- **최종 선택:** 일반 Context 3 / 목록형 Context 10을 유지한다.
- **선택 근거:** 목록 질문에 더 많은 근거를 담을 공간이 필요하다. 다만 L-02의 개선은 **Routing과 후보 구성의 결합 결과**이며 dynamic top-k만의 단독 효과로 단정하지 않는다. 
- **남은 한계:** 목록형 키워드 기반 분류가 표현을 놓칠 수 있고, Context 10은 긴 문서에서 추론 비용을 늘린다.

## 4. Chunking 개선 근거

- **기존 문제:** 초기 PDF는 본문과 표를 중복 적재했고, 기존 구조 분할은 제목 단독 chunk, PDF 목록 항목 절단, DOCX 코드 설명·표 행 절단을 만들 수 있었다.
- **비교/변경 내용:** 먼저 PDF 중복을 제거해 전체 **32 → 26** chunks로 줄였다. 이후 PDF·DOCX에 제목·목록·논리적 표 행을 단위로 묶는 `StructuredSplitterV2`를 적용했다. TXT는 sentence 분할을 유지했다.
- **결과:** 후속 구조 점검에서 **PDF 목록 절단 0건, DOCX 코드/표 행 절단 0건**으로 기록됐고 인덱스는 **26 → 24 chunks(10/6/8)**가 됐다. 질문 문구를 바꾸지 않고 기대 chunk만 v1.4에 재매핑했다.
- **최종 선택:** PDF·DOCX에 `structured_split_v2`, TXT에 `sentence_split`을 사용한다.
- **선택 근거:** 문서 구조와 근거 문장이 함께 남아야 검색·답변에 쓰기 쉽다. 
- **남은 한계:** 절단 0건은 이번 정리 요청에 제공된 구조 점검값이며 별도 원본 로그는 `results/`에서 확인되지 않았다. 단일 단위가 chunk 상한보다 길면 보조 sentence 분할이 적용되므로 새 문서에도 절단이 없다고 보장하지는 않는다.

## 5. Qdrant Metadata Payload

- **기존 문제:** 기존 payload의 `source`, `splitter`, `chunk_index`, `chunk_length`만으로는 collection과 원본 형식을 노드 자체에서 확인하기 어렵다.
- **비교/변경 내용:** 저장 시 `collection`, `source_type`을 추가했다. `source_type`은 `txt`·`pdf`·`docx`다. 두 새 필드는 임베딩 입력에서 제외한다.
- **결과:** 검색 결과의 출처·분할 위치를 추적할 수 있고, 두 새 metadata 문자열이 본문 앞에 붙어 임베딩 입력을 바꾸는 일을 막는다.
- **최종 선택:** 기존 4개 필드와 새 2개 필드를 Qdrant payload에 보관한다.
- **선택 근거:** 출처 추적 정보를 늘리면서 metadata 추가만으로 벡터 비교 조건이 바뀌는 것을 피한다.
- **남은 한계:** 페이지·섹션 위치는 loader와 chunker가 제공하지 않아 저장하지 않는다. 분할 방식 자체가 바뀐 26→24 재인덱싱은 별개의 변경이다.

## 6. Collection Routing

- **기존 문제:** 매 질문에서 세 collection을 모두 검색하면 무관한 chunk가 후보를 차지하고 검색 시간이 늘었다.
- **비교/변경 내용:** 서버 시작 시 collection 설명을 임베딩하고, 질문과의 **코사인 유사도**가 최고점의 0.65 이상인 collection을 복수 선택한다. 최고점이 0.18 미만이거나 선택에 실패하면 전체 검색으로 fallback한다.
- **결과:** **26-chunk 동일 인덱스** 비교에서 기대 collection 포함 **27/27**, 평균 선택 **3.00→1.59개**, 검색 MRR **0.835→0.865**, L-02 항목 충족 **2/3→3/3**이었다.
- **최종 선택:** 설명문 기반 다중 Collection Routing과 전체 검색 fallback을 유지한다.
- **선택 근거:** 복합 질문의 여러 근거를 살리면서 후보를 줄였다. 
- **남은 한계:** 임계값은 현재 임베딩 모델·설명문에 의존한다. fallback은 라우팅 실패 보호 장치이며 문서 범위 밖 질문 판별기는 아니다.

## 7. Semantic / Keyword / Hybrid 비교

| 26-chunk 동일 인덱스, 범위 내 27문항 | Semantic | Keyword | Hybrid |
|---|---:|---:|---:|
| 검색 Hit / MRR | 27/27 · 0.865 | 27/27 · 0.852 | 27/27 · **0.914** |
| 재랭킹 Hit / MRR | 27/27 · 0.944 | 27/27 · **0.963** | 27/27 · 0.944 |

- **기존 문제:** Semantic만으로 충분한지, BM25 단독 또는 Dense+BM25 결합이 답변 근거를 개선하는지 확인해야 했다.
- **비교/변경 내용:** Routing을 켠 **26-chunk(10/7/9) 동일 인덱스**에서 세 방식을 비교했다. Keyword는 BM25, Hybrid는 RRF 결합이다.
- **결과:** Hybrid의 검색 순위 이점은 최종 재랭킹 MRR에 남지 않았다. Keyword는 최종 MRR이 0.019 높지만 Hit는 세 방식 모두 27/27이었다.
- **최종 선택:** 최종 24-chunk 파이프라인은 Semantic Search를 유지한다.
- **선택 근거:** 한 지표의 최고값보다 검색 구조의 단순성과 현재 파이프라인의 안정성을 우선했다. 
- **남은 한계:** 이 표는 26-chunk 당시 비교이며 24-chunk에서 세 방식을 다시 맞대어 측정한 결과는 아니다. Hybrid 시간 측정에는 CPU 부하 교란 기록도 있다.

## 8. Re-ranking 비교

| 24-chunk 동일 조건, 일반 후보 cap 8 | current | alt | alt2 | none |
|---|---:|---:|---:|---:|
| 최종 Top-K MRR | **0.963** | 0.438 | **0.975** | 0.870 |
| 정답 chunk 탈락 | **0** | 9 | **0** | 3 |
| 정보 누락 | **0** | 10 | 2 | 4 |
| 문서와 모순되는 단정 | **0** | 0 | 1 | 1 |
| 평균 재랭킹 시간 | 10.275초 | 42.399초 | 10.400초 | 약 0초 |

- **기존 문제:** 재랭킹 모델의 순위 점수나 크기만으로 최종 답변 품질과 처리 비용을 판단하기 어렵다.
- **비교/변경 내용:** `current`(Dongjin), `alt`(Alibaba gte), `alt2`(dragonkue bge), `none`을 semantic·`adaptive_v2`·24-chunk 조건에서 비교했다.
- **결과:** alt2는 MRR 최고지만 누락 2건·모순 1건이 있었다. alt는 탈락 9건·누락 10건·약 42.4초, none은 빠르지만 탈락 3건·누락 4건·모순 1건이었다.
- **최종 선택:** `current = Dongjin-kr/ko-reranker`를 유지한다.
- **선택 근거:** current는 MRR 0.963과 함께 탈락·누락·모순이 모두 0건이었다. 
- **남은 한계:** 이 모델 비교의 일반 후보 cap은 **8**이었다. 이후 cap 10 변경은 current에서 별도로 평가했으며, 다른 모델을 cap 10으로 재비교한 결과는 없다. 모순은 답변 원문 재검토 결과다.

## 9. Candidate cap 8 / 10 / 12

| 일반 질문 후보 상한 | 8 | 10 | 12 |
|---|---:|---:|---:|
| 고정 질문 최종 Hit / MRR | 27/27 · 0.963 | 27/27 · 0.963 | 27/27 · 0.963 |
| noisy 성공 | 22/27 | **23/27** | **23/27** |
| 일반 질문 평균 재랭킹 시간 | 10.101초 | 10.752초 | 12.091초 |

- **기존 문제:** noisy Q-13 `본사 주소는`의 주소 chunk가 병합 후보 **9위**에 있었지만 cap 8에서 잘렸다.
- **비교/변경 내용:** 검색·MQ·current 재랭커와 최종 Context 3·10, 목록형 후보 cap 15를 고정하고 일반 후보 상한만 8/10/12로 비교했다.
- **결과:** cap 10에서 Q-13이 복구되고 cap 8 성공→10 실패는 0건이었다. cap 12의 noisy 추가 성공은 없으며 일반 재랭킹은 cap 10보다 약 **1.339초** 길었다.
- **최종 선택:** 일반 후보 cap **10**, 목록형 **15**를 기본값으로 둔다.
- **선택 근거:** 확인된 9위 정답 chunk를 살리면서 고정 질문 품질을 유지했고, cap 12의 추가 비용을 피했다. 
- **남은 한계:** 시간은 대표 일반 질문 6개×3회 CPU 측정이다. Noisy MQ 문구는 실행마다 달라질 수 있으므로 총점 차이를 전부 cap 효과로 돌릴 수 없다. Q-13은 세 실행의 MQ 문구·병합 순위가 같아 cap 효과를 별도로 확인했다.

## 10. System Prompt / Context / 출처 / Hallucination

- **기존 문제:** 검색된 근거 밖의 내용을 만들어 답하거나, 거절 답변에 관련 없는 출처를 붙이면 사용자에게 잘못된 근거를 제시하게 된다.
- **비교/변경 내용:** system·user prompt에서 **Context만 사용**, 외부 지식 금지, Context에 없으면 거절을 지시한다. 재랭킹 Top-K 문서를 순서대로 Context에 넣고 `temperature=0`으로 답변한다. `/chat`은 `sources`(파일명 목록), `retrieved_docs`(rank·file·chunk·retriever/rerank score·본문)를 반환하며 거절 시 `sources`를 비운다.
- **결과:** current의 24-chunk 고정 30문항 평가에서 범위 밖 질문 **3/3 거절**, 명백한 Hallucination **0건**이었다.
- **최종 선택:** 현재 Context 제한·거절 지시·출처 표시 구조를 유지한다.
- **선택 근거:** 관측된 거절·답변 품질을 충족하며, 거절 답변에서 출처를 비워 실제로 쓰지 않은 문서를 근거로 보이게 하지 않는다. 
- **남은 한계:** `sources`는 답변의 **claim별 인용**이 아니고, 출력 주장마다 문서와 대조하는 별도 사실 검증도 없다. 거절 판정은 답변 문구 marker에 의존하며 평가셋 밖의 Hallucination 0건을 보장하지 않는다.
